# DIA Business — حسابداری موبایلی مهندس برق (V1)

یک وب‌اپ حسابداری/مدیریت کسب‌وکار، **کاملاً سمت کاربر (Client-Side)**، **آفلاین-محور (Offline-First)** و **موبایل‌محور**، ساخته‌شده با HTML/CSS/JavaScript خالص (بدون فریم‌ورک، بدون بک‌اند، بدون وابستگی به CDN). مناسب اجرا روی GitHub Pages.

## این پروژه چیست؟

DIA Business برای یک کسب‌وکار مهندسی برق طراحی شده: مدیریت مشتریان، کالا (کابل، کلید و پریز، تابلو برق و ...)، خدمات فنی، پروژه‌ها، صدور فاکتور فروش با محاسبه خودکار تخفیف/مالیات، ثبت درآمد و هزینه، و گزارش‌گیری — همه به زبان فارسی، با تقویم شمسی و اعداد فارسی، و راست‌به‌چپ (RTL).

تمام اطلاعات در **IndexedDB** روی همان مرورگر/دستگاه ذخیره می‌شود؛ هیچ سروری در کار نیست.

## ساختار پروژه

```
/
├── index.html          نقطه ورود SPA
├── manifest.json        مشخصات PWA (آیکون‌ها، رنگ تم)
├── sw.js                 Service Worker برای کارکرد آفلاین
├── css/
│   ├── style.css         استایل اصلی برنامه
│   └── print.css         استایل مخصوص چاپ فاکتور/صورتحساب
├── js/
│   ├── app.js            راه‌اندازی برنامه، ثبت مسیرها، همگام‌سازی نوار پایین
│   ├── router.js         روتر ساده مبتنی بر hash (بدون رفرش صفحه)
│   ├── db.js              لایه IndexedDB + تنظیمات + Backup/Restore
│   ├── validators.js     لایه اعتبارسنجی خالص (بدون DOM/DB) با پیام‌های فارسی
│   ├── utils.js           فرمت اعداد/تاریخ فارسی، توست، دانلود فایل، عدد به حروف
│   └── views/             هر صفحه یک فایل مستقل
│       ├── dashboard.js
│       ├── customers.js
│       ├── customer-detail.js   (صورتحساب و گردش حساب مشتری)
│       ├── products.js
│       ├── services.js
│       ├── projects.js
│       ├── invoices.js
│       ├── accounting.js
│       ├── reports.js
│       └── settings.js
└── assets/               آیکون‌های PWA (بدون وابستگی به CDN)
```

## اجرای Local

چون از ES Modules استفاده شده، باز کردن مستقیم `index.html` با `file://` در برخی مرورگرها کار نمی‌کند. یک سرور ساده کافی است:

```bash
python3 -m http.server 8080
# سپس مرورگر را باز کنید: http://localhost:8080
```

یا با Node:

```bash
npx serve .
```

## اجرا روی GitHub Pages

1. محتوای این پوشه را در ریشه یک ریپازیتوری GitHub قرار دهید (یا در پوشه `docs/`).
2. در تنظیمات ریپازیتوری، گزینه GitHub Pages را فعال کنید.
3. تمام مسیرها به‌صورت نسبی (`./css/...`, `./js/...`) نوشته شده‌اند تا چه در ریشه دامنه و چه در زیرمسیر پروژه (`username.github.io/repo-name/`) درست کار کنند.
4. برنامه یک SPA مبتنی بر hash (`#/...`) است، بنابراین رفرش صفحه در هیچ مسیری باعث خطای 404 در GitHub Pages نمی‌شود.

## IndexedDB

پایگاه‌داده به نام `DIA_Business_DB` با Object Store‌های زیر ساخته می‌شود: `customers`, `products`, `services`, `projects`, `invoices`, `transactions`, `accounts`, `settings`. هر رکورد دارای `id` (تولید خودکار)، `createdAt` و `updatedAt` است. نسخه دیتابیس (`DB_VERSION`) برای migration در آینده در نظر گرفته شده — با افزایش این عدد و افزودن منطق در `onupgradeneeded`، می‌توان ساختار را در نسخه‌های بعدی تغییر داد بدون از دست رفتن اطلاعات کاربران فعلی.

## آفلاین / PWA

فایل `sw.js` تمام فایل‌های اپ (HTML، CSS، JS، آیکون‌ها) را در اولین بار اجرا کش می‌کند. پس از آن، برنامه بدون اینترنت هم باز می‌شود و کار می‌کند (چون داده‌ها در IndexedDB محلی هستند، نه روی سرور). وضعیت آنلاین/آفلاین در بالای صفحه نمایش داده می‌شود. برای رفع مشکلات کش قدیمی، عدد `CACHE` در `sw.js` را افزایش دهید.

## پشتیبان‌گیری (Backup / Restore)

از بخش «تنظیمات»:
- **خروجی پشتیبان**: یک فایل JSON شامل تمام اطلاعات دیتابیس دانلود می‌شود.
- **بازیابی پشتیبان**: با انتخاب همان فایل JSON، اطلاعات فعلی با محتوای فایل جایگزین می‌شود (با تأیید کاربر قبل از اجرا).

**توصیه می‌شود مرتب (مثلاً هفتگی) بکاپ بگیرید**، چون پاک شدن Cache/Storage مرورگر باعث از دست رفتن تمام اطلاعات می‌شود.

## نحوه توسعه پروژه (V2 و بعد از آن)

معماری طوری طراحی شده که افزودن موارد زیر بدون بازنویسی کلی ممکن باشد:
- تأمین‌کنندگان، خرید، چند انبار
- چک و اقساط، حساب‌های بانکی متعدد
- خروجی PDF واقعی (به‌جای Print مرورگر)
- چند شرکت / چند کاربر / Sync ابری (در صورت نیاز به بک‌اند)
- شماره اقتصادی و فاکتور رسمی مالیاتی

برای افزودن یک Store جدید: نام آن را به آرایه `stores` در `js/db.js` اضافه کنید (نسخه DB را افزایش دهید)، اعتبارسنج مربوطه را در `js/validators.js` بنویسید، و یک فایل View جدید در `js/views/` بسازید و در `js/app.js` مسیر آن را ثبت کنید.

## گزارش نهایی (بر اساس Audit این نسخه)

**مشکلات یافت‌شده در نسخه قبلی:**
- تنظیمات فاقد اطلاعات کسب‌وکار، شماره‌گذاری فاکتور و مالیات بود.
- فاکتور فقط وضعیت پرداخت‌شده/نشده داشت، نه ۵ وضعیت درخواستی.
- صفحه جزئیات/صورتحساب مشتری اصلاً وجود نداشت.
- **باگ حیاتی**: `print.css` کل `#modal-root` را در چاپ مخفی می‌کرد؛ چون محتوای فاکتور داخل همان مودال است، چاپ فاکتور عملاً یک صفحه خالی تولید می‌کرد.
- `manifest.json` فاقد آیکون بود (غیرقابل نصب صحیح به‌عنوان PWA).
- اعتبارسنجی فرم‌ها فقط با ویژگی HTML `required` انجام می‌شد؛ پیام خطای فارسی و متمرکز وجود نداشت.
- گزارش‌ها فقط ۳ نوع بودند و فیلتر تاریخ/مشتری/وضعیت نداشتند.
- مسیرها بدون `./` نوشته شده بودند (خلاف درخواست صریح برای GitHub Pages).
- یک باگ برنامه‌نویسی (Temporal Dead Zone) در فرم فاکتور باعث می‌شد افزودن ردیف کالا با خطا متوقف شود.

**چه چیزهایی اصلاح/اضافه شد:**
- ماژول مستقل `validators.js` با پیام‌های فارسی، پشتیبانی از اعداد فارسی/عربی، و وضعیت‌های متمرکز (کد وضعیت + ترجمه فارسی جدا).
- شماره‌گذاری فاکتور بر اساس تنظیمات (پیشوند + شماره شروع)، محاسبه خودکار مالیات، تخفیف کلی و ردیفی، «مبلغ به حروف».
- صفحه صورتحساب/گردش‌حساب مشتری با قابلیت چاپ.
- رفع باگ چاپ (روش جدید مبتنی بر کلاس موقت روی `body` به‌جای مخفی‌کردن کل مودال).
- آیکون‌های واقعی PWA (192/512/maskable/apple-touch-icon) بدون وابستگی به CDN.
- نشانگر آنلاین/آفلاین و همگام‌سازی نوار پایین با مسیر جاری.
- ۵ گزارش با فیلتر تاریخ/مشتری/وضعیت (فروش، درآمد، هزینه، بدهکاران، فاکتورها).
- تمام مسیرهای فایل با `./` بازنویسی شد.

**قابلیت‌های V1 (تست‌شده به‌صورت خودکار با یک اسکریپت Playwright که تمام ۲۰ سناریوی تست را اجرا کرد):**
مشتریان، محصولات، خدمات، پروژه‌ها، فاکتور فروش (چند قلم، تخفیف، مالیات اختیاری، ۵ وضعیت)، حسابداری ساده، ۵ گزارش با فیلتر، پشتیبان‌گیری/بازیابی، چاپ فاکتور و صورتحساب، خروجی PNG فاکتور، کارکرد کامل آفلاین بعد از اولین بار لود (تأیید‌شده با قطع واقعی شبکه در تست خودکار).

**قابلیت‌های باقی‌مانده برای V2:** تأمین‌کنندگان و خرید، چند انبار، PDF واقعی (غیر از Print مرورگر)، چک/اقساط، چند شرکت/چند کاربر، Sync ابری.

**آماده GitHub Pages؟** بله — بدون بک‌اند، مسیرهای نسبی، routing مبتنی بر hash (رفرش در هیچ مسیری 404 نمی‌دهد)، Service Worker با مسیر نسبی.
